# Week 14 Protection Requirements Matrix

| Data or operation | Classification and location | Objective | Selected control and evidence | Rejected or limited alternative | Residual limitation |
|---|---|---|---|---|---|
| Fixture password | Confidential; browser input and server password hash | Confidentiality and credential verification | Laravel `Hash` password hashing; masked field; login throttle; no password logs | Reversible encryption or a fast general-purpose hash | Fixture accounts remain operator-managed; no MFA in this prototype. |
| Opaque API session | Confidential; browser memory and hashed server record | Authenticity and limited lifetime | 64-character random token, SHA-256 server hash, two-hour expiry, logout deletion, HTTPS | Token in URL, local storage, or plaintext database column | A stolen live token works until logout or expiry; no refresh-token family. |
| Consultation agenda and schedule | Sensitive fictional research-service record; database and secure payload | Confidentiality, integrity, minimization | Role/ownership query; AES-256-GCM envelope; five-minute TTL; TLS; only six required payload fields | Sending the full consultation object or relying on encryption to justify extra fields | Authorized endpoints see plaintext during use; MariaDB at-rest encryption is outside local scope. |
| Envelope metadata | Security-sensitive; browser and API | Authenticity, freshness, correct recipient | Version, key ID, UUID, issued/expiry times, sender and recipient are authenticated as GCM additional data | Unauthenticated headers or timestamp outside the tag | Clocks must remain within the documented 30-second future skew. |
| Accepted message ID | Internal security record; MariaDB | Replay prevention and accountability | Unique database constraint and receipt; HTTP 409 on duplicate | In-memory cache only | Receipt retention is local and needs a future archival policy. |
| Server encryption key | Secret; ignored protected keyring | Confidentiality and integrity of envelope | 256 random bits, server-only file, no output, current plus previous key rotation | Key in Flutter, source, screenshot, or shared `.env.example` | Local file protection depends on Windows account and backup handling; no HSM/KMS. |
| TLS private key | Secret; ignored protected TLS directory | Server authentication and transport confidentiality | Short-lived 3072-bit RSA certificate, localhost SAN, TLS 1.2 minimum, trusted local CA | Browser warning bypass or plaintext browser-to-API call | Local CA has no online revocation service and must be removed after the controlled exercise if no longer needed. |
| Audit events | Internal; MariaDB and protected Laravel log | Accountability without disclosure | Correlation ID, event, entity, actor and allowlisted reason/message ID; no request body, token, key, ciphertext, or plaintext | Logging full requests for convenience | Host administrators can alter local logs; cryptographic log sealing is outside this prototype. |
| Configuration examples | Public tracked source | Reproducibility without secrets | Blank secret values, protected path setting, explicit HTTPS URL | Copying live `.env` into submission | Operators can still misconfigure file permissions or origins. |
